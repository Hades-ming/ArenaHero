# Arena Hero 资源调度与分散探索设计

## 背景与根因

当前战术虽然把资源坐标和已探索地形写入 `tactic_state.json`，但资源调度仍存在三处断裂：

1. 距 Core 超过 65 格的资源会从持久化资源池删除，导致“地图记住了资源”并不成立。
2. Worker 按遍历顺序逐个贪心认领资源，只保证局部最近，不能保证全队总路程最短。
3. 无资源时仍使用固定扫列，返航和绕障会让多个 Worker 恢复相同方向，长期集中在 Core 东南侧。

这三个问题共同造成了用户观察到的现象：地图上存在已知资源，但空闲 Worker 仍在东南区域重复移动。

## 最终目标

所有行为服务于“得到最多的资源”：优先把已知资源转化为可存储资源；没有可信资源任务时，以最大化新增视野覆盖率的方式探索；资源运输、战斗防御和手动干预后的恢复仍服从现有经济与安全策略。

## 设计决策

### 1. 持久化资源是提示，当前 Turn 是权威

- 当前可见资源立即加入 `_known_resources`。
- 已知资源不再因为距 Core 远而删除。
- 仅在以下情况下删除：
  - 当前 Turn 的完整状态重新照亮该坐标，并确认该格没有资源；
  - `HARVEST_SUCCEEDED` 事件明确报告该资源被采集，且当前 Turn 没有在同坐标重新显示资源。
- Core 迁移时保留全局资源与已探索地图；只清理 Worker 的临时路径、锁和探索目标。迁移不等于历史事实失效。

### 2. 每 Tick 全局重算资源任务

参与匹配的 Worker 必须为空载；载货 Worker 始终优先返航，站在当前可见资源上的空载 Worker 立即采集。

匹配目标按严格优先级排序：

1. 最大化已分配资源数，即 `min(空载 Worker 数, 可信已知资源数)`。
2. 在相同分配数下，最大化当前可见资源被领取数。
3. 在前两项相同下，最小化 Worker 到资源的 Manhattan 总距离。
4. 最后按 Worker UUID 和资源坐标稳定打破平局，确保相同状态产生相同计划。

每个资源最多分配一个 Worker，每个 Worker最多领取一个资源。匹配每 Tick 重新计算，因此新发现资源可立即由更近的空闲 Worker接管，不继承不合理的旧锁。

Worker 到资源的 Core 距离不再作为硬过滤条件。远端资源可能运输成本高，但在不存在其它已知资源时，主动采集的期望收益仍高于在已探索区域闲逛。A* 继续负责单 Tick 下一步移动和障碍绕行。

实现使用无第三方依赖的确定性最小费用流。边容量均为 1；为当前可见资源附加足够大的负奖励，使目标优先级不会被路程差覆盖。

### 3. 无任务 Worker 使用分散前沿探索

从持久化 `_explored_cells` 周边生成未探索前沿候选点，排除已知障碍和 Core 位置。候选评分依次考虑：

1. 目标附近可新增的未探索可见格数量；
2. 与已为其它 Worker 选择的目标之间的距离；
3. Worker 到目标的路程；
4. 坐标稳定排序。

采用确定性的最远点贪心分配，使空闲 Worker落在不同方向和不同前沿，而不是恢复相同扫列。每个 Worker 的探索目标保持稳定，直到目标附近已被充分探索、目标成为障碍、Worker 消失、Core 迁移，或出现资源任务。这样避免每 Tick 改目标造成振荡。

如果当前没有可用前沿候选，则使用围绕 Core 的多方向探索目标作为退化策略；不同 Worker仍必须分配到不同方位。

### 4. 与现有优先级的关系

Worker 行为顺序：

1. 携带地面 Beacon 时沿现有规则处理。
2. 载货返航或在 Core 上存入。
3. 空载且站在当前可见资源上时采集。
4. 执行全局资源匹配任务。
5. 没有资源任务时执行分散前沿探索。

战斗单位、Core 防御、攻击单位生产和手动动作覆盖规则保持不变。用户手动改变战场后，下一个完整 Turn 重新计算全部 Worker 任务。

## 状态与接口

- 新增 `_worker_resource_assignments(turn) -> dict[str, tuple[int, int]]`，只返回本 Tick 的坐标分配，不保存控制器。
- 新增 `_explore_targets: dict[str, tuple[int, int]]`，保存稳定的 Worker 探索意图。
- 新增 `_assign_explore_targets(...)`，为没有资源任务的空闲 Worker 选择互相分散的目标。
- `_known_resources`、`_known_obstacles`、`_known_enemy_cores`、`_explored_cells` 继续持久化。
- `_explore_targets` 不持久化；重启后由持久化地图确定性重建。

## 验收标准

1. 距 Core 超过 65 格的已知资源仍保留并分配给空载 Worker。
2. 当前可见资源在资源数大于 Worker 数时优先被领取。
3. 构造贪心反例时，全局分配总距离最小，且不受 Unit 输入顺序影响。
4. 载货 Worker不参与资源认领，一个资源不分给多个 Worker。
5. 重启加载持久化资源后，第一 Tick 即恢复资源分配。
6. 已知资源重新进入可见范围且为空时被删除。
7. 无资源时，多 Worker 的目标覆盖不同方向，且保持最小间距。
8. 障碍后的未知区域仍能成为探索目标。
9. 相同状态产生确定性相同计划。
10. 现有战斗、运输、Core 生产与 52 项基线测试不回归。

## 风险与约束

- Manhattan 距离只是匹配成本估计，真实障碍路程由 A* 修正；为避免每 Tick 对所有组合跑 A*，本轮不把完整路径长度加入匹配矩阵。
- 历史资源可能在视野外已被其他玩家采走；它仍是待复核提示。Worker 到达或重新照亮为空后会立即清除。
- 远端运输可能增加返航时间，但硬距离裁剪已经被实战证明会把可用资源永久遗忘。本轮优先保证“已知资源必消费”，后续再用采集成功率和往返时长做数据驱动衰减。
- 不新增第三方依赖，不修改 SDK，不保存 Turn 控制器，不提交 `.env`、运行日志或 `tactic_state.json`。
